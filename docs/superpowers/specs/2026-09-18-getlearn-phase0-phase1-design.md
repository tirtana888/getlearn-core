# Design Spec: getlearn.ai Phase 0 & Phase 1 Core Backend

**Date**: 2026-09-18  
**Status**: Approved / In-Design  
**Target Environment**: Railway (`getlearn-ai` project with managed PostgreSQL)

---

## 1. Executive Summary & Objective

`getlearn.ai` is a standalone Learner Intelligence Infrastructure providing canonical data models and APIs to track learning mastery, detect knowledge gaps, and recommend next-best actions across disparate Learning Management Systems (starting with Frappe LMS / Nusadaya Academy).

This specification establishes:
- **Phase 0**: The canonical OpenAPI 3.1 contract, canonical entity definitions, and envelope standards.
- **Phase 1**: The initial Fastify + TypeScript backend service skeleton connected to Railway PostgreSQL via Prisma ORM, implementing tenant isolation, event ingestion with idempotency, and naive mastery calculation.

## 3. Canonical Entities & Data Model

All business tables reside in Railway PostgreSQL and contain a mandatory `tenant_id` foreign key.

### Prisma Schema Entities
1. **Tenant**
   - `id`: String (UUID or slug)
   - `name`: String
   - `tokenBalance`: Int (default 100,000 units)
   - `createdAt`, `updatedAt`: DateTime

2. **Learner**
   - `id`: String (UUID)
   - `tenantId`: String (FK -> Tenant.id)
   - `externalRef`: String (opaque ID from LMS, e.g. LMS user docname; no PII)
   - Unique constraint: `[tenantId, externalRef]`

3. **LearningObjective**
   - `id`: String (opaque ID, e.g. `obj_fraction_add`)
   - `tenantId`: String (FK -> Tenant.id)
   - `label`: String (competency description)
   - `parentId`: String (optional hierarchy link)
   - Unique constraint: `[tenantId, id]`

4. **ContentItem**
   - `id`: String (opaque ID, e.g. `lesson_123`)
   - `tenantId`: String (FK -> Tenant.id)
   - `type`: Enum (`text`, `video`, `pdf`, `scorm`)
   - `sourceUri`: String (optional URL)
   - `objectiveIds`: String[] (array of mapped LearningObjective IDs)
   - Unique constraint: `[tenantId, id]`

5. **AssessmentItem**
   - `id`: String (opaque ID, e.g. `q_2451`)
   - `tenantId`: String (FK -> Tenant.id)
   - `itemType`: Enum (`mcq`, `short`, `essay`)
   - `promptText`: String (the question text)
   - `objectiveIds`: String[] (array of tested LearningObjective IDs)
   - Unique constraint: `[tenantId, id]`

6. **AssessmentEvent**
   - `id`: String (Idempotency key generated by connector, e.g. `evt_quiz_result_101`)
   - `tenantId`: String (FK -> Tenant.id)
   - `learnerId`: String (FK -> Learner.id)
   - `itemId`: String (FK -> AssessmentItem.id)
   - `isCorrect`: Boolean
   - `rawResponse`: String
   - `occurredAt`: DateTime
   - Unique constraint: `[tenantId, id]` (prevents double ingestion on network retries)

7. **MasteryRecord**
   - `id`: String (UUID)
   - `tenantId`: String (FK -> Tenant.id)
   - `learnerId`: String (FK -> Learner.id)
   - `objectiveId`: String (FK -> LearningObjective.id)
   - `score`: Float (0.00 to 1.00)
   - `evidenceCount`: Int (total assessment events evaluated)
   - `updatedAt`: DateTime
   - Unique constraint: `[tenantId, learnerId, objectiveId]`

## 4. API Endpoints Contract (Fase 0 & 1)

### 4.1. Registration (Upsert)
- `POST /v1/objectives`
  - Upsert single or batch `LearningObjective`.
- `POST /v1/content-items`
  - Upsert `ContentItem` mapping.
- `POST /v1/assessment-items`
  - Upsert `AssessmentItem` with question prompt.

### 4.2. Ingestion (Event Logging)
- `POST /v1/events`
  - Body:
    ```json
    {
      "event_id": "evt_unique_hash_981",
      "event_type": "assessment.answered",
      "external_learner_id": "usr_9f2a",
      "occurred_at": "2026-09-18T10:31:00Z",
      "payload": {
        "item_id": "q_2451",
        "is_correct": false,
        "raw_response": "B"
      }
    }
    ```
  - Behavior:
    1. Verify `event_id` hasn't been ingested for this tenant. If exists, return HTTP 200 with `{ "status": "duplicate_ignored" }`.
    2. Resolve or upsert `Learner` record by `external_learner_id`.
    3. Save `AssessmentEvent`.
    4. Trigger Phase 1 Naive Mastery Calculation for all `objectiveIds` linked to `item_id`.

### 4.3. Intelligence Query
- `GET /v1/learners/:id/mastery`
  - Returns current mastery scores across all attempted objectives for the learner.
- `GET /v1/learners/:id/gaps`
  - Returns objectives where `score < 0.70` (threshold configurable).
- `GET /v1/learners/:id/next-action`
  - Returns highest priority recommendation:
    - Action: `review` | `practice` | `reassess`
    - Target: `target_id` (ContentItem ID or AssessmentItem ID)
    - Reason: `reason_objective_id`

### 4.4. Tenant Admin
- `POST /v1/admin/tenants`
  - Create a new tenant and issue API key.

## 5. Phase 1 Naive Mastery Calculation Logic

$$\text{score} = \frac{\sum \text{isCorrect}}{\text{evidenceCount}}$$

- If `evidenceCount < 3`, `confidence = "low"`.
- If `score < 0.7`, flag as `gap`.
- Next action logic:
  - If `gap` exists: Recommend `review` on `ContentItem` covering the weakest objective.
  - If no `gap`: Recommend `practice` on next objective.

## 6. Implementation Milestones

1. **Phase 0**: Write `docs/openapi.yaml` (OpenAPI 3.1 specification).
2. **Phase 1 Infrastructure**: Initialize Fastify project, install dependencies (`@fastify/swagger`, `@fastify/swagger-ui`, `prisma`, `@prisma/client`, `zod`, `@unkey/api`).
3. **Database Migration**: Configure Prisma with Railway PostgreSQL connection string, enable `pgvector`, apply migration.
4. **Core Services & Handlers**: Implement routes, Unkey auth middleware with mock dev fallback, and naive mastery calculation.
5. **Verification**: Run end-to-end integration test validating event ingestion, idempotency, and mastery updates.
